# Terraform on yourproduct-backbone

## Worker parity
- Octopus worker = `yourproduct-octopus-02` image, Terraform **0.13.3**, Linux, SHARED "Hosted Ubuntu" dynamic workers. Local parity: a 0.13.3 binary under scratch (`releases.hashicorp.com/terraform/0.13.3/`) via `TFBIN`, or `hashicorp/terraform:0.13.3` in docker.
- Apply step runs `terraform apply -auto-approve` with a FRESH plan → the approval-step plan is NOT what gets applied. Re-run the read-only plan right before asking for approval.
- Lifecycle `MinimumEnvironmentsBeforePromotion: 0` means ALL environments in the phase (QA before Production), not "none".
- "timeout while waiting for plugin to start" / "Could not load plugin" / 14-min plans = worker shared with other tasks (aws v6 provider is huge to start). Retry when the pool is quiet. PROJ-15791. Same error on app Lambda projects when ~28 prod deploys fire at once (release 130) → cap concurrency.
- "state snapshot was created by Terraform v1.3.7, which is newer than current v0.13.3" at `init` = a LOCAL 1.x CLI wrote that state (any `state mv`/`import`/`apply`/`push`) → Octopus can never deploy that project again until image 03. Check `.terraform_version` (`state pull | jq`) BEFORE any state write; write with `TFBIN`=0.13.3 to keep Octopus working. Known 1.3.7: prod ResultsProcessor v4 (PROJ-15486, applied locally 2026-10-14).
- Image 03 exists: ECR repo `yourproduct`, tag `yourproduct-octopus-03` (TF 1.16.5 at `/usr/bin/terraform`, pushed 2026-10-13). Container comes from var `octopus-execution-container` (library set `YourProduct - Octopus` = `yourproduct:yourproduct-octopus-02`) → a 1.x root needs a PROJECT-scoped override + no `CustomTerraformExecutable`. ## Read-only plan recipe
`bash ~/.claude/skills/ama-terraform-backbone/scripts/tf-plan-readonly.sh <module> <Projects-N> <Environments-N> <label> [token=value ...]` — exports `origin/master` (or `SRCDIR=<worktree>`), swaps `Shared` in for the `modules` symlink, renders every `#{token}` from Octopus `variables/preview`, `terraform plan -lock=false`. Never apply/import/state-mv from it.
- Sensitive tokens come back `<<SENSITIVE>>` → pass `token=value`. `rds-password` is NOT marked sensitive in Octopus → preview prints it. Mask `password|secret|token` names before echoing a preview (leaked 2026-10-14, redacted).
- Windows + TF 0.13 traps: deep scratch dir → `.terraform/plugins/...` "filename too long" → `TF_DATA_DIR=C:/tfd/<label>`. `TF_PLUGIN_CACHE_DIR` → "Failed to install provider from shared cache" / "Could not load plugin" → don't set it. `cp -r` / `xargs cp --parents` of a root breaks the `modules` symlink ("Unreadable module directory") → `git archive | tar`.
- Container parity: `MSYS_NO_PATHCONV=1 docker run --rm -v "$(cygpath -w "$D"):/in" --entrypoint sh hashicorp/terraform:0.13.3 /in/run.sh`. BusyBox grep has no `--include` → `find . -name '*.tf' | xargs grep -l`.
- Roots with no Octopus project (Route53, Repositories, Kylin, Adco) use `environment/*.conf` partial backend configs and symlinked `provider.tf`/`global-variables.tf` (some dangling) → not plannable as checked out; audit via the state file + AWS CLI instead.

## Fleet sweep (every root x env + AWS inventory join)
- `scripts/sweep/README.md` — 8-step recipe: list states → index (parse-and-delete) → AWS inventory → join → render like Octopus → plan in the 0.13.3 container (plugin cache, N loops) → classify → scrub+clean. First run 2026-10-14: 465 states, 11k AWS objects, 113 plans in ~45 min.
- Octopus substitutes ONLY root-level `*.tf`/`*.tfvars(.json)` + the step's `Octopus.Action.Terraform.FileSubstitution` list (RabbitMq: `content/*.json`); var file = `Octopus.Action.Terraform.VarFiles` (Base roots: `rds.tfvars`/`iam.tfvars`/`elasticsearch.tfvars`). A root with no Octopus project (pricing/*, Embs-Snapshot, Route53, Repositories) must NOT be edited on a branch that builds: `_build/build.sh` fails the whole build at "Cannot find the project" (build 124).

## Reading the plan
- "Provider configuration not present" on a state written by TF 0.12 → state records `registry.terraform.io/-/aws`. Fix = `terraform state replace-provider registry.terraform.io/-/aws registry.terraform.io/hashicorp/aws` (state-only). NOT `state rm`, NOT destroy — the "orphan" is usually the live resource (Admin prod, Export prod 2026-10).
- Rehearse state surgery on a LOCAL COPY first: `terraform state pull > x.tfstate`, copy the root, `backend "local" { path = "x.tfstate" }`, replace-provider / `state mv` there, plan with `-var` overrides. Zero S3/AWS writes. Then do it for real, then plan again.
- State buckets have NO undo: `hs-<env>-terraform` versioning Suspended, every `*-remote-state-*` bucket never versioned (checked 2026-10-22). Before ANY real state write (`state rm/mv/replace-provider`, `import`, force-unlock): `state pull > <scratch>/<root>-<env>-pre.tfstate` (secret-bearing, outside git), keep until post-write plan is clean, then delete. Rollback = `state push -force <file>` with `TFBIN`=0.13.3 (its serial is lower than live, so plain push refuses).
- After real state surgery: confirm NO leftover lock — `aws dynamodb get-item --table-name hs-<env>-terraform-state-lock-dynamo --key '{"LockID":{"S":"<bucket>/<key>"}}'` → empty. Never `grep -v 'state lock'` surgery output (hides a failed release). Orphan lock → Octopus plan fails `Error acquiring the state lock: ConditionalCheckFailedException` (ExportProducer prod, 10-14 `state rm` lock found 10-21). Fix: confirm Who/Created = own finished run + no `terraform.exe` CLI running (`terraform-ls`/`ms-terraform-lsp` = VS Code, harmless) → `delete-item` conditional on lock ID.
- Fleet drift classes (survey 2026-10-14): (1) `mnd-*` ClientCorp governance tags added live → provider `default_tags { tags = local.mnd_tags }` + `mnd-tags.tf` locals (precedent Ingress/Certificates); (2) RDS `engine_version` Octopus var behind auto-minor-upgrade (var 15.15, live 15.17) → fix the VAR; (3) `storage_type "gp2"` vs live gp3 → code; (4) `new_<x>_rds_database` rename landed in QA/Staging (new instances 2024) but Production kept the old instance → `state mv old new` + prod vars to live values, never let it create+destroy; (5) `deletion_protection` only on the prod DB → `var.ENVIRONMENT == "production"`.
- State-bucket undo (2026-10-27): `hs-<env>-terraform` versioned in stg/qa/prod (dev Suspended). `*-remote-state-*` buckets (43; Base/Database/RDS via `#{tfstate_bucket}`, Admin, Blog, Storage) NOT versioned -> `state pull` copy before ANY state write there.
- State files hold secrets (RDS passwords, keys) → never cat; `jq '.resources[] | {type,name}'` + ids only; delete local copies when done. Bulk sweep (every state in the buckets, 469 files 2026-10-14): parse-then-`os.remove` each file in the same loop, never a persistent `states/` copy; mask `AKIA…` ids in the index. Rendered plan dirs (`.vars.tsv`, `*.tf` with preview values) and plan LOGS (ECS `container_definitions` JSON prints connection strings) are secret-bearing too → scrub logs against secret-named preview values, then `rm -rf` the render dirs + tar; scratchpad is not wiped at session end.
- `TF_PLUGIN_CACHE_DIR` is Windows-broken only — in the Linux container it works and is the only sane way to plan 100+ root×env pairs (one aws provider download per version, not per plan).

## Pipeline
- **ONE root per PR** (Reviewer One, 2026-10-20; PR #22 sweep declined): branch off master, that root only, read-only plans QA/Staging/Prod, PR → Reviewer One → merge → QA → Staging → Prod verified → next root. Each root PR pins `hashicorp/aws` exactly (`versions.tf` `required_providers`) to the version its plans used (Octopus log `Installed hashicorp/aws vX`). Precedent PR #25 (Cohorts, 6.69.1). Unpinned roots float to newest provider every run; Elasticsearch root pins `~> 2.70` (old) → own PR.
- **DB roots still public in code → `DB-PRIVATE-QUEUE.md`** (read before approving ANY backbone DB-root deploy).
- `_build/build.sh` creates one Octopus release per changed component dir on ANY branch; a branch push auto-deploys Staging and stops at approval where the project has an approval step. A push touching N roots = N releases → push reconciliation in small batches.
- After ANY backbone push or test release: list pending-approval ('Approve Terraform Plan') tasks, cancel your own. Stray extra-component releases carry drifted unsafe plans (Export: RDS 15.17->15.15, gp3->gp2). Approving = damage.
- Component match is a `grep -q "<dir>"` SUBSTRING: keep the trailing slash (PR #21: `Applications/AMA/Export` matched ExporterPlus).
- Branch build fails `fatal: bad object <sha>` right after `PREVIOUS_REF:` when the branch was cut before master moved: build.sh diffs against master's last-built revision (S3 `hs-teamcity-build-revisions/backbone/master`) and the shallow branch clone lacks it. Fix = rebase onto `origin/master`, push, build again (PR #21, 2026-10-14). A PR needs that green build before Bitbucket merges it.
- Release build number = Bitbucket pipeline build → `pipeline-build.sh yourproduct-backbone <n>` → branch + commit. Deployer `automation-sa` = pipeline-created.
- **After an apply touches a shared env's networking (SG, NLB, broker, listener): verify the env, same session.** `bash ~/.claude/skills/ama-cloudwatch-search/scripts/aws-sweep.sh staging --hours 1` + Graylog `environment:staging AND level:<=3 AND known_issue:"Suppress non prod alerts"` (the catch-all tag; an untagged sweep is blind on Staging, see `release-preflight.sh` 1b).
## Don'ts
